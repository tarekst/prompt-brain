# DeepSeek-V4-Flash

## Reasoning / Thinking
- **Ein Hybrid-Modell statt zweier IDs**: `deepseek-v4-flash` beherrscht Non-Thinking und Thinking; einen separaten Reasoner gibt es nicht mehr. Thinking ist **per Default an** (Default-Effort `high`) — wer V3-artige Direktantworten will, muss aktiv abschalten: OpenAI-Format `{"thinking": {"type": "enabled" | "disabled"}}` (im OpenAI-SDK in `extra_body`), Anthropic-Format `{"reasoning": {"effort": "none" | "low" | "high" | "max"}}` mit `none` = aus.
- Effort-Werte: `low | high (Default) | max`. Mapping angeforderter Stufen: low→low, medium→high, high→high, **xhigh→high**, max→max. Thinking ignoriert `temperature`, `top_p`, `presence_penalty`, `frequency_penalty` — Sampling-Anweisungen im Prompt-Umfeld sind dort toter Text.
- Die Chain-of-Thought kommt in `reasoning_content` auf derselben Ebene wie `content`. **Ohne** Tool-Calls muss sie in Folgeturns nicht mitgeschickt werden; **mit** Tool-Calls muss das intermediäre `reasoning_content` in die Kontext-Konkatenation und zurück an die API.
- Token-Ebene (Model Card): Reasoning wird als `<think>{reasoning}</think>` gerahmt, Non-Thinking durch ein sofortiges `</think>` nach dem Assistant-Marker kodiert; bei `reasoning_effort="max"` stellt das Template dem System-Prompt ein Präfix voran („Reasoning Effort: Absolute maximum with no shortcuts permitted…"). Drei benannte Modi: Non-think, Think High, Think Max (Think Max empfiehlt ≥ 384K Kontextfenster).

## Prompting-Stil
- System-Prompt ist erstklassig: Template ist `<｜begin▁of▁sentence｜>{system_prompt}<｜User｜>{user_message}<｜Assistant｜>` — er steht ganz vorn in der Sequenz.
- **JSON braucht drei Dinge gleichzeitig**: das Wort „json" im System- oder User-Prompt, ein Beispiel des gewünschten JSON-Formats im Prompt, und ein ausreichend hohes `max_tokens`, damit der String nicht mitten drin abbricht. Output-Steuerung sonst per **Chat Prefix Completion**: letzte Message `role: "assistant"` mit `prefix: True` gegen `base_url="https://api.deepseek.com/beta"`, kombiniert mit `stop` (z. B. `["```"]`) gegen nachlaufende Prosa.
- **Prompt-Reihenfolge ist kostenrelevant**: Context Caching ist ohne Codeänderung für alle aktiv, trifft aber nur bei **vollständigem Präfix-Match** einer persistierten Cache-Unit und arbeitet „best-effort" — daraus folgt: statisches Material (System, Referenzdokumente) nach vorn, Variables ans Ende (als Empfehlung nicht explizit dokumentiert, nur in den Beispielen so vorgeführt — unbelegt); Kontrolle über `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`.
- Tool-Schemata kommen über das `tools`-Feld; intern werden Aufrufe als DSML gerendert (`<｜DSML｜invoke name="…">`, Parameter mit `string="true"` für Rohstrings, `string="false"` für JSON-Werte) — relevant nur beim Handschreiben von Tool-Call-Beispielen. Lokale Deployments: Model Card empfiehlt `temperature = 1.0`, `top_p = 1.0` (im Thinking-Modus ohnehin wirkungslos).

## Stärken & Schwächen (prompt-relevant)
- Effizienz-Tier: MoE mit 284B total / 13B aktiviert, FP4+FP8 gemischt, Hybrid-Attention (Compressed Sparse Attention + Heavily Compressed Attention) plus Manifold-Constrained Hyper-Connections (mHC). Preis $0.14 / $0.28 pro 1M Input(Cache-Miss)/Output-Tokens bei Concurrency-Limit 2500 — ggü. V4-Pro ~3× günstigerer Input und 5× Concurrency. (Die Model Card nennt „27 % FLOPs / 10 % KV-Cache ggü. V3.2" ausdrücklich für **V4-Pro**, nicht für Flash.)
- Stärken (Benchmarkwerte, sofern nicht anders genannt = Non-Think-Spalte): Coding (HumanEval 69.5; Think High 88.4, Think Max 91.6), Mathe (GSM8K 90.8), Long Context (LongBench-V2 44.7); der Max-Modus hebt vor allem wissenslastige Aufgaben (SimpleQA-Verified 23.1 → 34.1).
- **Schwäche Faktenwissen**: SimpleQA-Verified 23.1 (Non-Think) / 28.9 (High) / 34.1 (Max) gegen V4-Pro mit 45.0 / 46.2 / 57.9 — wissenslastige Prompts brauchen eigenes Grounding oder gehören auf Pro.
- Weitere Limits: FIM Completion nur non-thinking; JSON Output liefert gelegentlich leeren `content` (Prompt anpassen); Think Max will ≥ 384K Kontext. Der Anthropic-kompatible Endpoint unterstützt keine Image-/Document-Blocks, keine `anthropic-beta`/`anthropic-version`-Header, kein `top_k`, kein `cache_control`, keinen MCP-Tool-Use, und ignoriert `budget_tokens`.

## Output- & Format-Konventionen
- **1M Kontextfenster, bis 384K Output-Tokens.** Unterstützt: JSON Output, Tool Calls, Responses API, Anthropic API, Chat Prefix Completion (Beta); FIM Completion nur im Non-Thinking-Modus. Aktuelle Version hinter der ID ist `DeepSeek-V4-Flash-0731`; dass die ID stets auf die jeweils neueste Version zeigt, ist so nicht dokumentiert (unbelegt).
- Base-URLs: `https://api.deepseek.com` (OpenAI-SDK), `https://api.deepseek.com/anthropic` (Anthropic-SDK), `https://api.deepseek.com/beta` (Prefill/FIM). Auf dem Anthropic-Endpoint mappen `claude-haiku*`/`claude-sonnet*` auf `deepseek-v4-flash`; unbekannte Modellnamen fallen ebenfalls darauf zurück.
- `response_format` kennt nur `text` (Default) und `json_object` — **kein `json_schema`**; strikte Schema-Einhaltung muss über Prompt + nachgelagerte Validierung erzwungen werden. Sampling: `temperature` 0–2 (Default 1), `top_p` bis 1 (Default 1), max. 16 `stop`-Sequenzen, `logprobs` mit `top_logprobs` 0–20, bis 128 Tool-Funktionen, `tool_choice` none/auto/required/spezifisch; `frequency_penalty` und `presence_penalty` werden nicht mehr unterstützt und bleiben wirkungslos.

## Migrations-Hinweise
- **VON DeepSeek-V4-Flash weg**: `thinking`/`reasoning_effort`-Parameter und jede `reasoning_content`-Behandlung entfernen; hat das Ziel keinen nativen Reasoning-Modus, explizite Chain-of-Thought-Anweisungen wieder in den Prompt schreiben; erzwingt das Ziel `json_schema`, das prompt-eingebettete JSON-Beispiel in ein echtes Schema überführen und das Pflicht-Literal „json" streichen; `presence_penalty`/`frequency_penalty` nur wieder einführen, wenn das Ziel sie kennt; `prefix: True`-Prefill durch das Prefill-Äquivalent des Ziels oder einen Stop-Sequence-Workaround ersetzen. Flash→Pro innerhalb der Familie braucht **keinen** Prompt-Rewrite (gleiche Parameter, gleiche Kontext-/Output-Limits) — nur wissenslastige Prompts rechtfertigen den ~3× teureren Input.
- **ZU DeepSeek-V4-Flash migrieren** (von `deepseek-v3` / `deepseek-chat` / `deepseek-r1` / `deepseek-reasoner`): Die Legacy-IDs sind **weg** — `deepseek-chat` und `deepseek-reasoner` waren nach dem 24.07.2026, 15:59 UTC endgültig nicht mehr erreichbar; offizielle Anweisung: „Keep base_url, just update model to deepseek-v4-pro or deepseek-v4-flash." Konkret: (1) Der Modell-Split chat-vs-reasoner wird zum **Mode-Flag** — ein früherer `deepseek-chat`-Prompt braucht jetzt `thinking: {"type": "disabled"}` bzw. `reasoning.effort: "none"`, ein früherer Reasoner-Prompt gar nichts. (2) `frequency_penalty`/`presence_penalty` aus dem Request löschen. (3) `temperature`/`top_p`-Tuning aus Reasoning-Prompts entfernen — R1-Ratschläge wie „setze temperature 0.6" sind wirkungslos. (4) Orchestriert der Prompt Tool-Calls, muss `reasoning_content` nun in den Folgeturn zurückgespielt statt gestrippt werden. (5) 1M Kontext ist Default, 384K Output möglich — Chunking-/Teilzusammenfassungs-Gerüste aus der V3/R1-Ära ersatzlos streichen. (6) Prompt umsortieren: statische Instruktionen/Referenzen nach vorn, weil Prefix-Caching nur volle Präfix-Treffer belohnt. (7) „Think step by step"-Scaffolding durch `reasoning_effort` low/high/max ersetzen — Denktiefe ist jetzt Parameter, nicht Prompt-Text.
